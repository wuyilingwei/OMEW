# 调研记录

- [现象] Overture 清单的 `terms.texts` 每种语言只有一句 Cloudflare 资源创建说明。 -> [结论] 不能表达软件许可、美术资产限制、第三方资产授权、免责声明与账户权限风险，需升级为正式 Markdown 条款。
- [现象] `ASSET-LICENSE.md` 已有经确认的中英文美术限制、捐助和成本回收广告边界。 -> [结论] 不改其规则；部署条款应在构建时读取并派生对应语言内容，避免手工复制后漂移。
- [现象] README 明确软件代码为 `AGPL-3.0-only`，当前 Overture 清单却声明 `AGPL-3.0-or-later`。 -> [结论] 清单标识必须改为 `AGPL-3.0-only`，与项目事实一致。
- [现象] 当前清单已有 Worker/D1/R2/Durable Objects、账户级 Worker 设置令牌等权限信息。 -> [结论] 正式条款需说明资源创建、费用与账户级 Worker 权限风险，且不能把部署器授权描述成仅限单一 Worker。
- [验证] Overture 目标契约实际执行构建、Wrangler dry-run、归档和清单解析。 -> [结论] 生成清单保留默认 `1.0.0`/`v1.0.0`，许可证标识为 `AGPL-3.0-only`，双语 Markdown 分别为 2930 与 6817 字符，中文资产全文和英文参考译文均来自当前 `ASSET-LICENSE.md`。
- [风险] 本轮验证覆盖生成清单的数据结构与 Markdown 内容，但没有在当前线上 Overture UI 中执行最终接受与部署流程。 -> [结论] 合并并覆盖发布附件后仍需在真实部署器中确认长条款的滚动、Markdown 渲染和确认门禁；本分支不发布、不部署。
- [边界] `ASSET-LICENSE.md`、软件版本和 `overture/recipe.js` 均未修改。 -> [结论] 保留既有美术规则、1.0.0 发布语义和部署配方历史 SPDX 文件头，仅校正应用清单对外展示的许可证标识。
